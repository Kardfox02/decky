# DECK_CONTRACT.md

**Статус:** MVP v0.2 · **Назначение:** единый источник истины для формата деки и требований к авторскому HTML. Поведение, тайм-ауты и приёмка самого плеера описаны в `ARCH.md`.

Нормативные слова **ДОЛЖЕН**, **ЗАПРЕЩЕНО** обозначают обязательные требования; **РЕКОМЕНДУЕТСЯ** — необязательные рекомендации. Все остальные описательные формулировки разъясняют эти требования и не вводят новых обязательств. Дизайн и процесс проверки вынесены в `DESIGN_GUIDELINES.md` и `VALIDATION.md`.

## 1. Расположение и идентификатор

- Корень дек — каталог `deck/` рядом с приложением.
- Каждая дека — непосредственная подпапка `deck/<deck_id>/`.
- `deck_id` равен имени папки и соответствует `^[A-Za-z0-9_-]+$`. Кириллица, пробелы и другие символы в **имени папки** запрещены.
- Внутри деки имена файлов могут содержать пробелы, кириллицу, `#` и `?` (при корректном URL-кодировании).
- Дека доступна в списке лишь при наличии валидного `deck.json` и удовлетворении проверкам пути.
- `deck_dir.resolve()` должен находиться внутри `deck_root.resolve()`; ссылка на директорию за пределами корня отвергается. Политика MVP допускает ссылку **внутри** корня, если остальные проверки пройдены. Для более строгой изоляции можно полностью запретить symlink-деки отдельным решением.
- Все пути файлов слайдов после `resolve()` обязаны оставаться внутри `deck_dir.resolve()`.

## 2. `deck.json`

Кодировка UTF-8 или UTF-8 с BOM (`utf-8-sig`). Верхний уровень — объект JSON.

```json
{
  "title": "Алгебра: функции",
  "slides": [
    { "file": "slides/01.html", "background": "#0F172A" },
    { "file": "slides/02.html", "background": "#FFFFFF" }
  ]
}
```

### Обязательные поля

| Поле | Требования |
|---|---|
| `title` | Строка, непустая после `strip()`; в UI отображается с обрезанными краевыми пробелами. |
| `slides` | Непустой массив объектов в порядке показа. |
| `slides[].file` | Непустая строка; относительный путь к существующему HTML-файлу внутри деки. |
| `slides[].background` | Строка, полностью совпадающая с `#[0-9A-Fa-f]{6}`. Обязательна у каждого слайда. |

### Ограничения `slides[].file`

- `file` **ДОЛЖЕН** быть относительным POSIX-путём, состоящим из непустых сегментов, разделённых ровно одним `/`. Например, `slides/01.html`.
- **ЗАПРЕЩЕНО:** начальный `/`, обратная косая черта `\`, двоеточие `:`, NUL (`\u0000` после JSON-декодирования), пустые сегменты (`a//b`, `/a`, `a/`), сегменты `.` и `..`, Windows drive/UNC-пути.
- После `(deck_dir / file).resolve()` результат **ДОЛЖЕН** оставаться внутри `deck_dir.resolve()`, удовлетворять `is_file()` и иметь `.suffix.lower() == '.html'`. Symlink на файл вне директории деки **ЗАПРЕЩЁН**.
- Для совместимости с Windows автор **НЕ ДОЛЖЕН** создавать в одной директории два пути, различающихся только регистром букв. Коллизии имён на регистронезависимых ФС проверяются отдельно при сборке деки.
- Символы пробела, `#`, `?` и кириллица в именах файлов разрешены; при сборке URL они **ДОЛЖНЫ** кодироваться как часть пути: POSIX-путь и `urllib.parse.quote(path, safe="/")`. Ни `#`, ни `?` в имени файла не интерпретируются как fragment/query.
- Повторное использование одного и того же `file` в нескольких записях `slides` **РАЗРЕШЕНО**: это разные позиции показа; документ каждый раз загружается заново.

**Политика неизвестных ключей MVP:** плеер **ДОЛЖЕН** игнорировать дополнительные свойства корневого объекта и объектов слайдов. Они не меняют работу плеера и не являются частью контракта. Автору **ЗАПРЕЩЕНО** рассчитывать на них; поля `id`, `formatVersion`, `theme`, `transition`, `pageId`, `settings` не нужны. ID деки определяется именем директории.

## 3. HTML-слайд и координатная система

- **Один HTML-файл = один слайд.**
- Viewport документа iframe фиксирован: **1920 × 1080 CSS px**.
- Плеер отображает iframe масштабированием `transform: scale(s)` с сохранением отношения 16:9, центрирует, не обрезает и не растягивает по отдельным осям.
- Масштаб `s = min(available_width / 1920, available_height / 1080)`, где размеры — **фактическая доступная область для слайда**, без интерфейсных панелей плеера.
- Автор **ДОЛЖЕН** настроить заполнение viewport и не рассчитывать на CSS/JS-инъекции плеера. Это можно сделать напрямую или через общий `assets/theme.css`, подключаемый относительной ссылкой. `<meta name="viewport">` не требуется: viewport iframe фиксирован.

```css
*, *::before, *::after { box-sizing: border-box; }
html, body {
  width: 100%;
  height: 100%;
  margin: 0;
  overflow: hidden;
}
```

- Значимый контент ДОЛЖЕН помещаться внутри 1920 × 1080 без горизонтальной/вертикальной прокрутки, наложений и обрезки. **ДОЛЖНА** соблюдаться безопасная область — минимум 64 px от края; рекомендуется 64–96 px (детали — в `DESIGN_GUIDELINES.md`).
- **ЗАПРЕЩЕНО** использовать `overflow: hidden` как способ скрыть уже переполненный важный контент.
- Значимый текст и код ДОЛЖНЫ быть настоящим HTML-текстом, а не изображением.

## 4. Фон и ресурсы

- `background` из `deck.json` — цвет **подложки плеера**, а не CSS-переопределение содержимого iframe.
- Автору РЕКОМЕНДУЕТСЯ задать фон `body`, базовый цвет которого близок к `background` слайда. Если используется градиент, его краевые/доминирующие цвета также должны быть близки к `background`, чтобы не возникало заметного скачка. Точное совпадение не требуется.
- Разрешены обычные HTML, CSS, JavaScript, `<script type="module">`, Canvas, WebGL, локальные изображения и шрифты при поддержке соответствующих ресурсов встроенным браузерным движком.
- Автор **ДОЛЖЕН** использовать только относительные URL локальных ресурсов (например, `../assets/logo.svg` из `slides/01.html`). Корневые URL (`/assets/logo.svg`, `/deck/...`), `//host/...` и элемент `<base>` **ЗАПРЕЩЕНЫ**. Относительный путь разрешается от URL текущего HTML, оставаясь внутри деки. Это правило относится к `src`, `href`, CSS `url()`, `fetch()`, `import` и подобным ссылкам.
- Запросы обслуживаются в пространстве URL `/deck/<deck_id>/...`; автор **НЕ ДОЛЖЕН** прописывать этот префикс вручную.
- **MIME-совместимость:** `.html` (`text/html`), `.css` (`text/css`), `.js`/`.mjs` (JavaScript MIME), `.svg` (`image/svg+xml`), `.woff2` (`font/woff2`), `.wasm` (`application/wasm`) — целевой набор для спайка HTTP-сервера и движка `pywebview`. До прохождения интеграционных тестов поддержка каждого из этих типов **НЕ ГАРАНТИРУЕТСЯ**; особенно проверить ES-модули и WebAssembly. После спайка зафиксировать подтверждённый набор в `ARCH.md`.
- **Для переносимой офлайн-деки** все обязательные для отображения/интерактивности ресурсы ДОЛЖНЫ быть локальными: без обязательных CDN, внешних API, внешних шрифтов и сетевых изображений.
- Автор **ДОЛЖЕН** использовать системные шрифты или локальные `.woff2` внутри деки. Внешние шрифты и CDN **ЗАПРЕЩЕНЫ**. Для одинаковой раскладки на Windows/macOS/Linux рекомендуется задавать явные fallback-стеки и оставлять запас ≥10% по ширине и высоте.
- РЕКОМЕНДУЕТСЯ хранить общую палитру, типографику и базовый reset в `assets/theme.css` и подключать его относительной ссылкой `../assets/theme.css`. Это файл деки, а не поле `deck.json`.
- URL на внешние origin и переходы из iframe технически возможны, но не входят в гарантированный сценарий просмотра и навигации. Вызовы `requestFullscreen()`, autoplay аудио/видео без пользовательского жеста и браузерные API, требующие permissions/iframe `allow`, **НЕ ГАРАНТИРУЮТСЯ**. Автор **НЕ ДОЛЖЕН** делать основной сценарий зависимым от них.
- Ресурсы рекомендуется хранить в `assets/` (не обязательное имя папки).

## 5. Жизненный цикл, переходы и состояние

- Один iframe; **без crossfade и без пула iframe**.
- Последовательность перехода: **fade-out → обновление подложки → изменение `iframe.src` → ожидание `load` → fade-in**.
- При смене `src` старый документ уничтожается. Возврат к слайду — полная новая загрузка.
- JS-переменные, события, формы и игровое состояние слайда **не сохраняются между переходами**.
- Интерактивный слайд **ДОЛЖЕН** начинать работу корректно при прямом открытии и повторной загрузке, иметь определённое начальное состояние и **ДОЛЖЕН** содержать локальную кнопку сброса/повтора, если предполагает несколько попыток.
- Пошаговое раскрытие материала **РЕКОМЕНДУЕТСЯ** делать отдельными слайдами, а не внутренними шагами: при возврате на слайд его состояние сбрасывается.
- Дека не имеет гарантированного долговременного состояния. Не рассчитывать на `localStorage` между запусками: `pywebview` с `private_mode=True` по умолчанию удаляет его при завершении сеанса; внутри сеанса хранилище совместное.
- Во время перехода плеер **игнорирует** дополнительные команды смены слайда (без очереди).
- Тайм-ауты определены **только в `ARCH.md`**: `HEAD`-preflight около **5 с**, ожидание `iframe load` около **8 с**, значения зафиксированы в коде плеера. `HEAD` обязателен для MVP: fallback на `GET` не предусмотрен. Дека не может настраивать эти значения. При расхождении документации источником истины для поведения плеера является `ARCH.md`.
- `iframe` `load` не гарантирует завершение асинхронного JS, загрузки созданных кодом ресурсов или готовность WebGL. Критически важный первый кадр не должен зависеть от длительных асинхронных операций.
- При `prefers-reduced-motion: reduce` плеер отключает fade, сохраняя проверку и ожидание загрузки; автору рекомендуется учитывать предпочтение и внутри HTML.

## 6. Клавиатура и ввод

- Плеер обрабатывает `keydown` на стадии всплытия в shell и в документе iframe (только пока iframe same-origin и обработчики подключены).
- Плеер игнорирует события, если источник — `input`, `textarea`, `select`, `contenteditable`, `[role="textbox"]`, `[role="slider"]`, `video`, `audio`; при `Ctrl`, `Alt` или `Meta`; а также если уже установлен `event.defaultPrevented`.
- Слайд вправе использовать стрелки для собственной механики, но в таком случае **ДОЛЖЕН** вызывать `event.preventDefault()` **только для реально обработанных нажатий**.
- При фокусе внутри вложенных iframe или после перехода на внешний origin навигация с клавиатуры не гарантируется.
- Кнопки и тесты должны быть доступны мышью; рекомендуется поддерживать `Tab`, `Enter` и `Space`, не завязывая управление только на стрелки.

## 7. Границы доверия

- `deck/` содержит **исполняемый код**, а не безопасные данные. Открывать только доверенные деки.
- Shell и деки расположены на одном origin. iframe не sandboxed.
- Слайд может обращаться к `parent.document`, `parent.pywebview.api` и разделяемому в рамках сеанса `localStorage`/cookies/IndexedDB.
- JS API, предоставляемый shell, в MVP ограничен read-only `list_decks`, однако это **не изолирует** HTML от DOM оболочки.
- Проверки JSON, расширения и разрешённых путей не делают недоверенный HTML безопасным. Не импортировать непроверенные сторонние деки.
- Презентации рекомендуется писать без доступа к API оболочки и родительскому DOM.

## 8. Ограничения MVP и обработка ошибок

- Нет публичного JS-bridge для слайдов, `Player.*`, `postMessage`, `srcdoc`.
- Нет предзагрузки слайдов, пула iframe, очереди навигации, API сохранения прогресса или специального кэша HTML.
- `HEAD`-preflight проверяет только доступность основного HTML в момент запроса. Он **не проверяет** вложенные ресурсы, корректность JS, интерактивность или отсутствие ошибок отрисовки.
- Между `HEAD` и `GET` файл может исчезнуть. В таком случае сервер может ответить 404, а iframe способен сгенерировать событие `load` даже на ошибочной странице. **По текущей приёмке штатный экран ошибки гарантируется, если основной HTML отсутствует уже на этапе `HEAD`-preflight.** Если файл исчез после успешного `HEAD`, но до `GET`, это известная гонка: HTTP 404 и событие iframe `load` не гарантируют отображение штатной ошибки. Отдельное обнаружение HTTP-ошибок при `GET` — возможное будущее улучшение `ARCH.md`.
- Ошибки локальных ресурсов или выполнения JS не диагностируются встроенным `HEAD`-preflight.

## 10. Чек-лист приёмки

- [ ] Имя деки соответствует `^[A-Za-z0-9_-]+$`; директория не выходит из `deck/` после `resolve()`.
- [ ] `deck.json` валиден, имеет непустой `title` и непустой `slides`.
- [ ] Каждый `file` — относительный, без `\`, `:`, NUL, пустых сегментов, `.`/`..`, внутри деки, существует, `.html`; нет коллизий регистра имён для Windows.
- [ ] Каждый `background` соответствует `#RRGGBB`.
- [ ] HTML занимает 1920 × 1080, без прокрутки и обрезки значимого содержимого; значимый контент внутри безопасной области ≥64 px.
- [ ] Базовый цвет фона `body` близок к `background`; при градиенте нет заметного скачка.
- [ ] Ресурсы используют относительные URL, без начального `/`, `//` и `<base>`; не выходят за деку.
- [ ] Все обязательные ресурсы локальны; нет обязательных CDN и критической зависимости от сети.
- [ ] Шрифты системные или локальные `.woff2`; внешних шрифтов/CDN нет; запас ≥10%.
- [ ] Общая тема и reset вынесены в `assets/theme.css` (если используется); ссылка относительная.
- [ ] Цели клика не меньше 64 × 64 CSS px; доступны `Tab`/`Enter`/`Space`.
- [ ] Первый полезный кадр не зависит от долгих асинхронных операций; общая анимация слайда не дольше 3–4 с.
- [ ] Интерактивность корректна после перезагрузки и возврата на слайд; предусмотрена локальная кнопка сброса/повтора там, где нужны повторные попытки.
- [ ] Слайд не перехватывает навигацию, кроме намеренно обработанных событий.
- [ ] Используются только доверенные HTML-деки.
- [ ] Пройдены применимые проверки из `VALIDATION.md`.
