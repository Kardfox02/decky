# ARCH.md — decky

> Минимальный десктопный плеер HTML-презентаций. Этот документ — единственный контракт для реализации MVP. Не добавлять возможности «на будущее».

## 1. Задача

decky открывает презентации из папки `deck/` рядом с исходным приложением, показывает их список с поиском и переключает HTML-слайды с плавным затуханием.

**Входит в MVP:**
- при запуске создать `deck/`, если её нет;
- найти доступные презентации в подпапках `deck/`;
- показать список названий и поиск по названию (без учёта регистра);
- открыть презентацию и листать её слайды кнопками и стрелками;
- выводить каждый слайд в области 16:9 с сохранением пропорций;
- использовать фоновый цвет слайда из `deck.json`, включая во время переходов;
- переключать полноэкранный режим плеера через JS Fullscreen API, если webview его поддерживает;
- показывать понятные ошибки вместо белого/пустого окна;
- иметь кнопку обновления списка (файлы могли измениться с момента запуска).

**Не входит:** редактор, импорт/экспорт, учётные записи, серверная бизнес-логика, SQLite, JSON-хранилище состояния, сохранение прогресса, телеметрия, плагины, поддержка дополнительных форматов, связь `Player.*` со слайдами, сканирование файловой системы по расписанию, установка/автообновление, crossfade, второй iframe, очередь переходов. Доверенные HTML-файлы пользователь размещает самостоятельно.

## 2. Стек

- Python 3.10+ и `pywebview` — одно нативное окно, встроенный сервер статических файлов и **один** небольшой JS↔Python вызов для перечня дек.
- Vanilla HTML/CSS/JavaScript — интерфейс и управление презентацией.
- Никаких FastAPI, Flask, React, Vue, Node.js, Vite, SQLite и дополнительных Python-зависимостей.

`pywebview` используется как оболочка браузера, а не как фреймворк приложения.

## 3. Структура

```text
decky/
├── main.py
├── index.html
├── app.css
├── app.js
├── requirements.txt
└── deck/                         # создаётся при запуске
    ├── algebra/
    │   ├── deck.json
    │   ├── slides/
    │   │   ├── 01.html
    │   │   └── 02.html
    │   └── assets/
    │       └── graph.png
    └── physics/
        ├── deck.json
        └── slides/
            └── 01.html
```

Для MVP **корень приложения** — директория с `main.py` и `index.html`. `deck/` располагается относительно директории приложения, а не текущей рабочей директории процесса:

```python
APP_ROOT = Path(__file__).resolve().parent
DECK_ROOT = APP_ROOT / "deck"
```

Наш код не использует `cwd` для поиска `deck/` или `index.html`. Как именно `pywebview` резолвит entrypoint, проверяется спайком ниже.

Поведение с установленным исполняемым файлом определить отдельно при разработке установщика. При упаковке в EXE ресурсы интерфейса и пользовательские презентации могут храниться отдельно; сейчас не пытаться упаковать папку дек внутрь односоставного exe.

Entrypoint должен поднимать встроенный HTTP-сервер `pywebview`, а не открываться через `file://`. Конкретный способ (относительный или абсолютный путь к `index.html`) фиксируется после спайка на выбранной версии `pywebview`. Критерий проверки: `window.location.href` начинается с `http://127.0.0.1`, `fetch('/deck/...')` из оболочки возвращает `200`, а `HEAD` для существующей и отсутствующей статики возвращает ожидаемые статусы. Если сервер не поддерживает `HEAD`, MVP несовместим с выбранной конфигурацией: fallback на `GET` не используется. Проверить запуск из исходников при разных `cwd` и зафиксировать версию `pywebview` в `requirements.txt`.

## 4. Формат презентации

Каждая непосредственная подпапка `deck/` — кандидат в презентацию. Презентация существует, если в подпапке есть валидный `deck.json`.

Пример `deck/algebra/deck.json`:

```json
{
  "title": "Алгебра: функции",
  "slides": [
    { "file": "slides/01.html", "background": "#0F172A" },
    { "file": "slides/02.html", "background": "#FFFFFF" }
  ]
}
```

**Единственные обязательные поля:**
- `title`: непустая строка — название в списке и поиске;
- `slides`: непустой массив в порядке показа;
- `slides[].file`: относительный к директории конкретной презентации путь к `.html`-файлу;
- `slides[].background`: CSS-цвет формата `#RRGGBB` (например, `#111827`). Обязателен для каждого слайда.

ID презентации = название её директории. Отдельный `id`, `formatVersion`, `theme`, `transition`, `pageId`, `settings`, версии API и другие поля не нужны.

Фоновый цвет управляет **подложкой плеера** под HTML-слайдом, но не переписывает CSS внутри HTML. Это именно подложка, а не гарантия цвета слайда: если `html`/`body` внутри iframe непрозрачны, они перекрывают её. Автору стоит задавать тот же цвет `body`, чтобы избежать несовпадений при загрузке. Подложка применяется до начала появления нового iframe.

### Валидация

- `deck.json` читается как `utf-8-sig`; верхний уровень — объект.
- `title` должен быть строкой и оставаться непустым после `strip()`; в список попадает значение без ведущих и хвостовых пробелов.
- `slides` — непустой массив объектов.
- Директории дек: разрешены имена `[A-Za-z0-9_-]+` для простого построения URL. Это осознанный компромисс: папки с кириллицей или пробелами не поддерживаются.
- Разрешённый каталог деки после `resolve()` должен оставаться **внутри** `DECK_ROOT.resolve()`; symlink-дека наружу отбрасывается.
- `slides[].file` должен быть непустой строкой и относительным POSIX-путём из непустых сегментов, разделённых одним `/`. Запрещены абсолютные пути, `\\`, `:`, NUL, пустые сегменты, сегменты `.` и `..`, включая варианты, которые после `resolve()` всё ещё находятся внутри деки. После `(deck_dir / file).resolve()` путь обязан оставаться **внутри** директории этой деки (`Path.is_relative_to()`), быть файлом (`is_file()`) и иметь расширение `.html` без учёта регистра (`.suffix.lower() == ".html"`).
- Дополнительные свойства корневого объекта и объектов `slides` игнорируются; повтор одного и того же значения `slides[].file` разрешён и означает отдельную позицию показа.
- `background` соответствует `re.fullmatch(r"#[0-9A-Fa-f]{6}", ...)`.
- При ошибке одной деки остальные должны продолжать отображаться. Ошибочную деку не показывать среди доступных; вывести краткое описание ошибки в консоль Python. Если корректных дек нет — показать пустое состояние с текстом, который предлагает создать подпапку с `deck.json` и проверить формат, если папки уже есть.
- Содержимое HTML не парсить и не изменять.

Эта валидация защищает контракт и корректность путей, а **не** делает сторонние скрипты безопасными. В MVP предполагаются локальные доверенные презентации.

## 5. Контракт HTML-слайда: 16:9

Рабочая область слайда — **1920 × 1080 CSS-пикселей**. Это базовое разрешение, под которое проектируются презентации. Плеер вписывает её в доступную область окна, сохраняя пропорцию 16:9 (`contain`). Не обрезает слайд и не растягивает его по отдельным осям.

- Любой размер окна: масштаб `s = min(availableWidth / 1920, availableHeight / 1080)`.
- HTML в iframe имеет фиксированный viewport **1920 × 1080 CSS px**; его визуальная область масштабируется равномерно через CSS `transform: scale(s)`.
- `.slide-frame` имеет размер `1920 × 1080`, позиционируется по центру и масштабируется: `position: absolute; left: 50%; top: 50%; transform: translate(-50%, -50%) scale(s); transform-origin: center center;`.
- Контейнер слайда (`.stage`) занимает доступную область, имеет нейтральный фон и `overflow: hidden`. Пересчёт масштаба выполняется через `ResizeObserver`; минимальный размер окна задаётся при создании окна, чтобы масштаб не становился нулевым.
- Центрировать получившийся прямоугольник. Оставшееся место вокруг занимает нейтральный фон приложения.
- В iframe разрешён обычный HTML, CSS, JavaScript, `<script type="module">`, Canvas, WebGL и относительные ссылки на ресурсы внутри деки.
- Для полного заполнения области автор HTML должен использовать `html, body { width:100%; height:100%; margin:0; overflow:hidden; }`. Сам плеер содержимое файла не изменяет.
- Один HTML-файл = один слайд. Плеер не знает ничего про внутренние элементы слайда.

**Важный компромисс MVP:** при уходе со слайда документ в iframe уничтожается при смене `src`; при возврате HTML загружается заново. Состояние JS/вводов внутри слайда между переходами не гарантируется. Долговременное состояние дек отсутствует.

## 6. Интерфейс

### Начальный экран

- Заголовок `decky`.
- Поле поиска по названиям дек, фильтрация по мере ввода, без учёта регистра.
- Список дек, отсортированный по названию; при совпадении `title` — по `id`.
- Если `title` совпадает у нескольких дек, показывать `id` второй строкой, чтобы их можно было различить.
- Кнопка «Обновить», повторно запрашивающая список с диска.
- Клик по элементу списка открывает первый слайд.
- Если дек нет: «В папке deck/ пока нет презентаций. Создайте подпапку с deck.json. Если папки уже есть, проверьте формат deck.json».
- Если по запросу нет совпадений: «Ничего не найдено».

### Просмотр презентации

- Кнопка «К списку». Она доступна всегда, в том числе во время перехода, и отменяет его.
- Название презентации.
- Область слайда 16:9.
- Кнопки «Назад» и «Далее»; на границах отключены. Во время перехода они отключены и игнорируются.
- Счётчик `текущий / всего`.
- Клавиши `←` и `→` — переход между слайдами.
- Кнопка «Полный экран» и клавиша `F` переключают полноэкранный режим, если фокус не в поле ввода.

Навигация с клавиатуры должна работать и после клика внутри iframe: поскольку обе страницы одного origin, shell после каждого `iframe.load` привязывает `keydown`-слушатель в фазе всплытия к документу iframe и один раз — к документу оболочки. Обработчик:

- игнорирует `input`, `textarea`, `select`, `contenteditable`;
- игнорирует элементы с `role="textbox"` и `role="slider"`, а также `video`/`audio`;
- игнорирует события с `Ctrl`, `Alt` или `Meta`;
- не действует, если `event.defaultPrevented` уже выставлен слайдом;
- оборачивает доступ к `contentWindow.document` в `try/catch` на случай cross-origin перехода.

При вводе в текстовых полях стрелки не перехватываются. Слайды не получают дополнительный JS bridge, но из-за same-origin могут обращаться к оболочке; это описано в разделе «Границы доверия».

Если iframe уводит пользователя на внешний origin, клавиатурная навигация внутри него не гарантируется. Вложенные iframe внутри слайда — известное ограничение: при фокусе во внутреннем документе клавиатура может не работать. Подобная навигация вне контракта деки.

Fullscreen применяется к `#player-view` (toolbar + stage). Если `document.fullscreenEnabled === false`, кнопка скрыта или disabled. Выход — по Escape, повторному нажатию кнопки или клавише `F`. При ошибке слайда и при «К списку» сначала вызывается `document.exitFullscreen()`, затем показывается соответствующий экран. После входа/выхода fullscreen масштаб пересчитывается.

Для доступности iframe получает `title`, а счётчик — `aria-live="polite"`.

## 7. Загрузка и плавные переходы

Используется **ровно один iframe**. Переход последовательный: старый документ исчезает, затем появляется новый. Настоящий crossfade не используется.

Все действия проходят через одну функцию `goTo(index)`:

1. Если `transitioning === true`, индекс совпадает с текущим или выходит за границы — выйти.
2. Синхронно установить `transitioning = true` и `gen = ++generation`.
3. Выполнить `HEAD`-preflight нового HTML: `fetch(url, { method: "HEAD", cache: "no-store", signal })` с таймаутом ~5 с. Если ответ не ok или произошёл таймаут — показать полноэкранный error view слайда.
4. Плавно погасить текущий iframe: `opacity: 1 → 0` за 100 мс (`transitionend` с fallback-таймером).
5. В момент, когда iframe прозрачен, сменить фон контейнера на новый `background` и выставить `iframe.src` нового слайда.
6. Дождаться `load` нового документа или таймаута ~8 с.
7. Плавно показать новый документ: `opacity: 0 → 1` за 150 мс.
8. Обновить счётчик и доступность кнопок; снять `transitioning`, если `gen` всё ещё актуален.

Итого 250 мс анимации, не считая загрузки. Для локальных файлов пауза минимальна; во время загрузки виден фон контейнера, поэтому белого кадра нет.

После каждого `await` проверяется `gen !== state.generation`. Если переход устарел, он молча завершается и не трогает DOM.

**Отмена и гонки:**
- «Вперёд»/«Назад» во время перехода игнорируются. Очередь переходов не нужна.
- «К списку» доступна всегда: увеличивает `generation`, абортит `fetch`, снимает `load`-обработчик, очищает таймеры, переводит iframe на `about:blank`, сбрасывает `opacity`, при активном fullscreen выходит из него, ставит `transitioning = false` и показывает список.
- `openDeck(deck)` увеличивает `generation`, отменяет возможный pending-переход, сбрасывает iframe, `transitioning` и `slideIndex`, затем вызывает `goTo(0)`.
- В `finally` перехода `transitioning` сбрасывается только при совпадении `gen` с `state.generation`. Отменённый переход не должен менять состояние нового.

**Ошибки загрузки:** событие `iframe.load` само по себе не гарантирует успешный HTTP-ответ. `HEAD`-preflight проверяет доступность основного HTML, но не ресурсов и не выполнение JS; остаётся и окно TOCTOU между проверкой и загрузкой. При ошибке preflight или таймауте загрузки плеер скрывается и показывается полноэкранный error view с сообщением и единственной кнопкой «К списку». Кнопки «Повторить» и навигация в этом состоянии отсутствуют; повторное открытие деки начинается с первого слайда. Если активен fullscreen, перед показом ошибки вызывается `document.exitFullscreen()`. Глубокая диагностика произвольного HTML и мониторинг каждой картинки/библиотеки в MVP не входят.

**Страница без анимаций:** при `prefers-reduced-motion: reduce` fade-анимации отключаются, но `HEAD`-preflight и ожидание `load` остаются.

## 8. Python API — ровно один метод

```python
class DeckApi:
    def __init__(self, deck_root: Path):
        self._deck_root = deck_root

    def list_decks(self) -> list[dict]:
        """Читает подпапки deck/, проверяет манифесты, возвращает готовые данные."""
```

`_deck_root` хранится как приватный атрибут, чтобы `pywebview` не пытался рекурсивно экспортировать его как часть API.

Возвращаемое значение:

```json
[
  {
    "id": "algebra",
    "title": "Алгебра: функции",
    "slides": [
      { "url": "/deck/algebra/slides/01.html", "background": "#0F172A" },
      { "url": "/deck/algebra/slides/02.html", "background": "#FFFFFF" }
    ]
  }
]
```

URL собирается из id деки и относительного пути слайда через POSIX-разделители и `urllib.parse.quote(..., safe="/")`, чтобы корректно работать с пробелами, `#`, `?` и не-ASCII символами. Сортировка выполняется в Python по `(title.casefold(), id)`. Возвращаются только plain-типы: `list[dict]`, строки.

`list_decks()` идемпотентно создаёт `deck/` через `_deck_root.mkdir(parents=True, exist_ok=True)`. Если создать папку или прочитать её нельзя, метод поднимает понятную ошибку; JS ловит rejection и показывает экран ошибки. Процесс не должен падать трейсбеком до открытия окна.

После этого `main.py` открывает `index.html` через `webview.create_window("decky", url=..., width=1280, height=800, min_size=(960, 600), js_api=DeckApi(DECK_ROOT))` и запускает `webview.start()`. Заголовок окна — `decky`. Конкретный вид entrypoint (относительный или абсолютный путь) определяется спайком из §3; `file://` не используется.

Для вызова API JS дожидается `pywebviewready`; затем обращается к `window.pywebview.api.list_decks()`. Если событие не пришло за 5 секунд, показывается экран ошибки с кнопкой «Повторить». Никаких других Python API-методов не требуется.

Список перечитывается **только** при запуске и по кнопке «Обновить». Нет фонового наблюдения за файловой системой.

## 9. Состояние в JS

Достаточно:

```js
const state = {
  decks: [],
  activeDeck: null,
  slideIndex: -1,
  transitioning: false,
  generation: 0
};
```

`slideIndex = -1` означает, что слайд ещё не показан; после успешного перехода хранится индекс текущего слайда. `generation` увеличивается при принятом `goTo`, `openDeck` и возврате к списку.

Допустимы локальные ссылки на iframe, элементы DOM, `AbortController`, таймеры и обработчик `load`. Нет Redux, классов `Store`, сохранения состояния на диск, кэша HTML и событийной шины.

## 10. Ошибки и границы

Ожидаемые ошибки обрабатываются в точках вызова. Глобальные `unhandledrejection` и `window.onerror` используются только для диагностики: пишут в `console.error` и не заменяют текущий экран.

| Ситуация | Поведение |
|---|---|
| `deck/` отсутствует | Python создаёт её автоматически |
| `deck/` пуста или все деки битые | Пустое состояние с инструкцией и подсказкой проверить `deck.json` |
| `deck.json` отсутствует/некорректен | Пропустить деку, warning в консоль |
| Ошибка создания `deck/` или прав | Rejection `list_decks` → экран ошибки с «Повторить» |
| `pywebviewready` не пришёл за 5 с | Экран ошибки с «Повторить» |
| Ошибка `list_decks` | Экран ошибки с «Повторить» |
| `HEAD`-preflight слайда не ok | Полноэкранный error view с «К списку»; плеер скрыт |
| Таймаут загрузки iframe | Полноэкранный error view с «К списку»; плеер скрыт |
| HTML-файл отсутствует на этапе `HEAD`-preflight | Полноэкранный error view с «К списку»; плеер скрыт |
| HTML-файл исчез между успешным `HEAD` и загрузкой iframe | Известная гонка: штатный error view и отсутствие страницы 404 не гарантируются |
| Неожиданное исключение в shell | `console.error`, без смены экрана |

Ошибка слайда не оставляет «Повторить» и навигацию: единственное действие — «К списку». Если активен fullscreen, сначала вызывается `document.exitFullscreen()`.

Плохой JS внутри слайда не должен менять логику shell по контракту. Но iframe **не sandbox**: выполнение произвольного доверенного HTML без ограничений не является границей безопасности или гарантией отсутствия зависаний.

## 11. Порядок реализации

1. Спайк `pywebview`: entrypoint, локальный HTTP-сервер, доступ к `/deck/...`, `HEAD`, MIME, кэш, Fullscreen API, фиксация версии в `requirements.txt`.
2. Создать `main.py`, `index.html`, `app.js`, `app.css`, `requirements.txt`.
3. При старте создавать `deck/` (идемпотентно в `list_decks`).
4. Реализовать `list_decks()` с валидацией JSON, путей, symlink и URL-кодированием.
5. Показать список дек, поиск, обновление и пустое состояние.
6. Добавить область 1920×1080 и масштабирование без искажения пропорций.
7. Показывать HTML в `iframe.src`, сохраняя работу относительных ресурсов.
8. Добавить кнопки навигации, стрелки при фокусе внутри iframe и fullscreen-переключатель.
9. Добавить переход: `HEAD` → fade-out → смена фона/`src` → `load`/таймаут → fade-in.
10. Проверить ошибки, отмену перехода и быстрые клики по навигации.

## 12. Приёмочные проверки

- Пустой запуск: `deck/` создана; интерфейс содержит инструкцию.
- Добавление папки с валидным `deck.json` и нажатие «Обновить» отображает новую деку.
- Поиск работает по части названия без учёта регистра.
- Две деки с одинаковым `title` различимы в списке по `id`.
- Слайды переключаются в порядке массива `slides`.
- CSS/JS/изображения/ES-модули с относительными путями загружаются из папки деки.
- В области любого размера слайд сохраняет соотношение **16:9** и полностью помещается; внутренний viewport iframe — 1920×1080.
- Цвет подложки меняется в момент смены `src` и соответствует `background`.
- Переход плавный: fade-out → фон → fade-in, без промежуточного белого кадра.
- Клавиши работают при фокусе в HTML-слайде, но не перехватываются в текстовых полях, `contenteditable`, `role="textbox"`, `role="slider"`, `video` и `audio`.
- Кнопка «Полный экран» и клавиша `F` входят и выходят из fullscreen; Escape выходит; после выхода 16:9, масштаб и клавиатура продолжают работать.
- Если webview не поддерживает Fullscreen API, кнопка скрыта или disabled.
- Cross-origin переход внутри слайда не роняет shell; клавиатура в нём может не работать.
- Многократные быстрые нажатия не создают второй iframe и не ломают текущий индекс.
- «К списку» во время перехода корректно отменяет его; при активном fullscreen сначала выполняется выход из него.
- Слайд, отсутствующий на этапе `HEAD`-preflight, даёт полноэкранный error view только с «К списку», без навигации и «Повторить». Удаление файла между успешным `HEAD` и загрузкой iframe остаётся известной гонкой без гарантированного error view.
- После правки HTML/CSS/JS/картинки и ухода со слайда/возврата показывается новая версия; «Обновить» перечитывает только список и не перезагружает открытый слайд.
- При 125%, 150%, 200% DPI и дробном `scale` текст читаем, а клики внутри iframe попадают в элементы без смещения.
- Symlink-дека наружу пропускается.
- Имена файлов с пробелами, `#`, `?` и кириллицей загружаются.
- `prefers-reduced-motion: reduce` — переход мгновенный.
- После смены слайда старый документ уничтожен; возврат перезагружает слайд.
- Ошибка `list_decks` и таймаут `pywebviewready` дают экран ошибки с «Повторить».
- В DOM всегда не больше одного iframe.

## 13. Границы доверия и известные ограничения

- Все деки и оболочка живут на одном origin. Слайд может обращаться к `parent.document` и `parent.pywebview.api`; API должен оставаться строго read-only.
- `localStorage`, cookies и IndexedDB общие для оболочки и всех дек в рамках сессии. При `private_mode=True` (по умолчанию в `pywebview`) они не сохраняются между запусками, но внутри сессии общие.
- `deck/` — это исполняемый код, а не данные. Открывать можно только доверенные презентации.
- iframe не используется с `sandbox`: это сломало бы доступ к `contentDocument` и клавиатурную навигацию.
- Cross-origin переходы и вложенные iframe внутри слайда — вне гарантий клавиатурной навигации.
- `background` — подложка плеера, а не переопределение CSS слайда.
- Один iframe уничтожает состояние старого слайда при смене `src`. Если таймаут случился после смены `src`, старый документ уже уничтожен; автоматическое восстановление предыдущего слайда не выполняется, показывается полноэкранный error view.
- `HEAD` проверяет только основной HTML; ошибки ресурсов и JS внутри слайда не диагностируются.
- Встроенный сервер раздаёт всю директорию entrypoint, включая `main.py`, `requirements.txt` и остальные файлы корня. Для локальных доверенных дек это допустимо; секреты в корне приложения не хранить.
- Статика отдаётся с `Cache-Control: no-cache, no-store, must-revalidate`; фактическое соблюдение проверяется в спайке на выбранном webview.
- «Обновить» перечитывает только список дек и не перезагружает открытый слайд. Чтобы увидеть правки HTML/CSS/JS, нужно уйти со слайда и вернуться или переоткрыть деку; автоперезагрузки нет.
- Fullscreen зависит от поддержки WebView. Если `document.fullscreenEnabled === false` или `requestFullscreen()` отклоняется, кнопка скрыта/disabled, а режим считается недоступным; Python API для этого не добавляется.
- `deck/` рядом с приложением может быть недоступна для записи при установке в защищённую директорию; поведение для EXE будет определено установщиком.

## 14. Запрещённые усложнения MVP

Не вводить `Player.*`, `bridge.js`, `postMessage`, `srcdoc`, второй iframe, crossfade, iframe-пул или предзагрузку всех слайдов, очередь переходов, SQLite, сохранение прогресса, модель событий, дополнительный сервер, сборку фронта, автоматическое обновление папки `deck/`, конвертацию файлов, мониторинг ресурсов слайда, отдельный модуль `decks.py`, GUI-автотесты, любые представления деки помимо `deck.json` + HTML.

**Принцип:** если возможность не нужна для списка презентаций, поиска, показа HTML-слайда 16:9, перехода на следующий слайд или fullscreen-режима, не реализовывать её.
