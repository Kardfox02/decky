- Не добавлять функции вне MVP.
- Не добавлять второй iframe, crossfade, очередь переходов, пул слайдов, предзагрузку всех слайдов, `decks.py`, SQLite, FastAPI, сборку фронта, GUI-автотесты и дополнительные Python-зависимости.
- Использовать `APP_ROOT = Path(__file__).resolve().parent`, `DECK_ROOT = APP_ROOT / "deck"`; не использовать `cwd` для поиска `deck/` или `index.html`.
- Названия дек и сообщения выводить через `textContent`, не через `innerHTML`.
- Не менять HTML-содержимое слайдов.
- После каждого этапа запускать проверки этапа и коротко отчитываться: что изменено, какие команды выполнены, что проверено, какие остались риски.

- Если этап выявил противоречие в `ARCH.md` или `DECK_CONTRACT.md` в их области ответственности, остановиться и сообщить о нём, а не придумывать новое поведение.

## Этап 0. Спайк pywebview

**Цель:** до написания приложения подтвердить, что `pywebview` поднимает локальный HTTP-сервер и отдаёт `/deck/...`.

**Задачи:**
1. Создать и активировать виртуальное окружение.
2. Установить `pywebview`, зафиксировать точную версию для `requirements.txt`.
3. Подготовить временный `index.html`, временную деку `deck/sample/slides/01.html` и файлы для MIME-проверок: `.js`, `.mjs`, `.css`, `.wasm`, `.json`.
4. Проверить два варианта entrypoint:
   - относительный `index.html`;
   - абсолютный путь `str(APP_ROOT / "index.html")`.
5. Для каждого варианта проверить:
   - `window.location.href` начинается с `http://127.0.0.1`;
   - `fetch('/deck/sample/slides/01.html')` возвращает `200`;
   - приложение открывается при запуске `python main.py`;
   - приложение открывается при запуске `python /абсолютный/путь/main.py`;
   - поведение не зависит от текущей рабочей директории терминала.
6. Проверить `HEAD` для статики:
   - существующий HTML — `200` и `Content-Type: text/html`;
   - отсутствующий файл — `404`;
   - если `HEAD` не поддерживается, остановить реализацию MVP и зафиксировать несовместимость: fallback на `GET` контрактом не предусмотрен.
7. Проверить MIME для `.js`, `.mjs`, `.css`, `.wasm`, `.json`; на Windows отдельно убедиться, что `.js` не отдаётся как `text/plain`.
8. Если MIME сломан, добавить перед `webview.start()`:
   - `mimetypes.add_type("text/javascript", ".js")`
   - `mimetypes.add_type("text/javascript", ".mjs")`
   - `mimetypes.add_type("application/wasm", ".wasm")`
9. Проверить корень статического сервера: `fetch('/main.py')` и `fetch('/app.js')`. Зафиксировать, что сервер раздаёт всю директорию entrypoint.
10. Проверить кэш: изменить HTML, CSS, JS и картинку, уйти со слайда и вернуться; убедиться, что видна новая версия. Отдельно зафиксировать, что «Обновить» перечитывает только список.
11. Проверить Fullscreen API:
    - `requestFullscreen()` на тестовом контейнере (будущий `#player-view`) и `document.documentElement.requestFullscreen()`;
    - вход/выход, Escape, клавиатура внутри iframe, сохранение 16:9;
    - `document.fullscreenEnabled`.
12. Выбрать способ entrypoint, который гарантированно поднимает HTTP-сервер.
13. Зафиксировать версию `pywebview`, способ entrypoint и результаты проверок сервера/кэша/fullscreen в `ARCH.md` §3, §8 и §13. Если fullscreen не работает, убрать его из MVP в §1/§6/§12 и оставить только ограничение в §13.

**Критерий готовности:**
- есть подтверждённый рабочий способ запуска;
- `fetch('/deck/...')` из оболочки возвращает `200`;
- `HEAD` работает для существующего и отсутствующего файла; fallback не используется;
- MIME для `.js`/`.mjs` корректен или определена правка через `mimetypes.add_type`;
- известно, раздаёт ли сервер корень приложения;
- известно, соблюдается ли `no-store` в выбранном webview;
- известно, работает ли `requestFullscreen()`;
- `file://` не используется;
- версия `pywebview` известна.

**Стоп-точка:** если локальный сервер не отдаёт `/deck/...` или не поддерживает `HEAD` для статики, не продолжать реализацию, а сообщить о проблеме. Если fullscreen не работает, зафиксировать это, скорректировать `ARCH.md` и не добавлять фичу.

## Этап 2. Python API и валидация

**Файлы:** `main.py`.

**Задачи:**
1. Реализовать `DeckApi` с приватным `_deck_root`.
2. Реализовать `list_decks()`:
   - идемпотентно создать `DECK_ROOT`;
   - перебрать непосредственные подпапки;
   - проверить имя папки по `[A-Za-z0-9_-]+`;
   - проверить, что `resolve()` каталога деки остаётся внутри `DECK_ROOT.resolve()`;
   - прочитать `deck.json` как `utf-8-sig`;
   - проверить `title` после `strip()`;
   - проверить непустой массив `slides`;
   - проверить каждый `file`: непустой относительный POSIX-путь из непустых сегментов, без `\\`, `:`, NUL, `.` и `..`; после `resolve()` путь остаётся внутри деки, существует и имеет `.suffix.lower() == ".html"`;
   - проверить `background` через `re.fullmatch(r"#[0-9A-Fa-f]{6}", ...)`;
   - игнорировать дополнительные свойства манифеста и объектов слайдов; разрешать повтор одного `file` как разные позиции показа;
   - построить URL с POSIX-разделителями и `urllib.parse.quote(..., safe="/")`;
   - отсортировать деки по `(title.casefold(), id)`.
3. При ошибке одной деки писать warning в лог и пропускать её; остальные деки возвращать.
4. При ошибке создания/чтения `DECK_ROOT` поднимать понятную ошибку, чтобы JS показал экран ошибки.
5. Вернуть только plain-типы: `list[dict]` и строки.

**Проверки:**
- временная валидная дека попадает в результат;
- дека без `deck.json` пропускается;
- битый JSON пропускается;
- пустой `title` и пустой `slides` пропускаются;
- абсолютный путь, `\\`, `:`, NUL, пустой сегмент, `.`/`..` и не-`.html` файл пропускаются;
- дополнительные свойства не вызывают ошибку; повтор одного `file` остаётся двумя позициями в результате;
- symlink-дека наружу пропускается (на поддерживаемой ОС);
- файл с пробелом, `#`, `?` или кириллицей получает корректно закодированный URL;
- сортировка не зависит от порядка файлов в файловой системе.

**Критерий готовности:**
- `DeckApi(DECK_ROOT).list_decks()` возвращает ожидаемые данные;
- ни одна ошибка одной деки не ломает весь список;
- URL в ответе соответствует файлам на диске.

## Этап 6. Переходы, отмена и ошибки загрузки

**Файлы:** `app.js`, `app.css`.

**Задачи:**
1. Реализовать `HEAD`-preflight с `AbortController`, `cache: "no-store"` и таймаутом ~5 с.
2. Реализовать fade-out iframe за 100 мс с `transitionend` и fallback-таймером.
3. В момент прозрачности iframe менять фон `.slide-frame` на новый `background` и выставлять `iframe.src`.
4. Ждать `load` с таймаутом ~8 с.
5. Реализовать fade-in за 150 мс.
6. Ввести `generation`: увеличивать при принятом `goTo`, `openDeck` и возврате к списку.
7. После каждого `await` проверять актуальность `generation`.
8. В `finally` сбрасывать `transitioning` только при совпадении `gen`.
9. «К списку» должна отменять переход: abort `fetch`, снять `load`-обработчик, очистить таймеры, перевести iframe на `about:blank`, при активном fullscreen выйти из него.
10. «Вперёд»/«Назад» во время перехода игнорировать; очередь не создавать.
11. При ошибке preflight или таймауте загрузки скрывать плеер и показывать полноэкранный error view с сообщением и единственной кнопкой «К списку». Не добавлять «Повторить» и навигацию в этом состоянии.
12. Если активен fullscreen, перед показом error view вызывать `document.exitFullscreen()`.
13. При `prefers-reduced-motion: reduce` отключать fade, но сохранять preflight и ожидание `load`.

**Проверки:**
- быстрые многократные нажатия не создают второй iframe;
- «К списку» во время перехода не оставляет висящих таймеров и не ломает следующий запуск;
- при слайде, отсутствующем до `HEAD`-preflight, показывается полноэкранная ошибка; удаление между успешным `HEAD` и загрузкой iframe фиксируется как известная непокрытая гонка;
- в error view нет «Повторить» и навигации;
- повторное открытие деки начинается с первого слайда;
- во время загрузки виден фон, без белого кадра;
- после перехода в DOM остаётся один iframe.

**Критерий готовности:**
- переход работает по последовательности `HEAD → fade-out → фон/src → load → fade-in`;
- отмена и гонки не меняют текущий индекс;
- ошибка слайда показывает полноэкранный error view только с «К списку» и не оставляет пустой экран.
